# 0004. Сервер не раскрывает связку имя ↔ никнейм ↔ эмблема

- Дата: 2026-08-27 (внесено задним числом)
- Статус: принято

## Контекст

У каждого участника три идентичности: настоящее имя (публично), никнейм (тайна) и
эмблема на бейдже (видна вживую, но неизвестно, чья). Вся игра состоит в том, чтобы
связать их между собой, наблюдая за людьми.

## Решение

Клиенту никогда не уходит связка «никнейм ↔ имя ↔ эмблема». Игрок получает
раздельно: список реальных имён с идентификаторами (для выстрела и защиты), табло
с никнеймами, никнейм своей цели без имени и без эмблемы, свою собственную
эмблему и текстовые подсказки об эмблеме цели.

Чужие эмблемы не отдаются вообще. Эмблемы рендерятся в SVG на сервере, поэтому
клиент не знает даже, из каких атрибутов они собраны.

## Почему

Если связка есть в ответе API, побеждает тот, кто открыл инструменты разработчика.
Сеть локальная, HTTP без шифрования, никаких иллюзий насчёт «клиент не посмотрит»
быть не может. Единственная надёжная защита — не отправлять того, что не нужно
показывать.

## Последствия

Нельзя показать в приложении галерею всех эмблем, каталог участников с эмблемами
или что-либо подобное — и не нужно (см. [0006](0006-shot-by-real-name.md)).
Подсказки уходят готовым текстом, а не атрибутами, иначе их можно было бы
сопоставить автоматически. Каждая новая ручка API обязана проверяться на это
правило: оно важнее удобства.
