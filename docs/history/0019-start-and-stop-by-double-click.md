# 0019. Запуск и остановка сервера — двойным щелчком

- Дата: 2026-08-29
- Статус: принято

## Контекст

Ведущий на игре не обязан уметь пользоваться консолью. Запуск двойным щелчком по
`start.cmd` был с самого начала ([0001](0001-local-server-and-buildless-client.md)),
а вот остановки не было вообще: единственным способом было закрыть нужное окно или
нажать в нём `Ctrl+C`. За несколько дней игры окно уходит за другие, сворачивается,
теряется на втором рабочем столе, а на вопрос «как выключить» ответа в проекте не
было.

Второй запуск поверх первого приводил к неразборчивому падению: `EADDRINUSE` со
стеком вызовов, из которого ведущий не узнает, что сервер уже работает.

Заодно выяснилось, что русские сообщения самого `start.cmd` ведущий никогда не
видел в читаемом виде: файл лежит в UTF-8, а консоль Windows по умолчанию в cp866,
так что «Node.js не найден» превращалось в мусор — ровно в тот момент, когда
сообщение важнее всего.

## Решение

Появился `stop.cmd`: двойной щелчок останавливает сервер и сообщает, что игра
сохранена. Чтобы не искать процесс наугад и не задеть чужой Node, сервер при старте
пишет свой PID в `data/server.pid` и убирает файл при выходе.

`start.cmd` этой же отметкой пользуется: если сервер уже работает, он говорит об
этом по-русски и не запускает второй. Оба скрипта переключают кодовую страницу на
UTF-8, поэтому их сообщения читаются.

Сервер проверяет занятость порта до запуска и объясняет отказ словами. В баннер
добавлены две строки: окно должно оставаться открытым и как игру остановить.

## Было / Стало

Было: `start.cmd` для запуска, остановка — «закройте окно» в документации.

Стало: `start.cmd` и `stop.cmd`, и ни одной команды, которую нужно набирать руками.

## Почему

Порт проверяется до запуска, а не по событию ошибки, потому что на Windows Node
успевает выдать «слушаю» раньше отказа: второй экземпляр печатал полный баннер с
адресами и QR, и только под ним — ошибку. Ведущий в такой картине уверен, что
сервер работает.

Отметку с PID сервер трогает осторожно: не перезаписывает чужую, если процесс из
неё жив, и удаляет только свою. Первая версия этого не делала, и упавший второй
экземпляр уносил с собой отметку работающего первого — то есть ломал ровно тот
механизм, ради которого затевался.

Останавливать сервер кнопкой в пульте не стали: пульт открыт в браузере рядом с
игровыми экранами, случайное нажатие останавливает игру для всех, а поднять её
обратно можно только с ноутбука. Цена ошибки несопоставима с экономией одного
двойного щелчка.

## Последствия

В `data/` появился второй файл. При переносе игры на другой ноутбук копировать
нужно по-прежнему только `state.json`: `server.pid` относится к запущенному
процессу, а не к игре.

Остановка через `stop.cmd` — принудительная: `taskkill` не даёт процессу
попрощаться. Потерять при этом можно не больше последних 200 мс изменений — на
столько отложена запись состояния, — то есть на практике ничего.

Отметка может остаться после жёсткой перезагрузки ноутбука. Оба скрипта такую
отметку распознают по отсутствию живого процесса и убирают, а решение «запускаться
или нет» сервер принимает всё равно по порту, а не по файлу: PID может достаться
чужому процессу, и отказываться из-за этого запускать игру было бы хуже всего.
