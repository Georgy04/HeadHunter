# 0002. Состояние в JSON-файле вместо базы данных

- Дата: 2026-08-27 (внесено задним числом)
- Статус: принято

## Контекст

Игре нужно помнить игроков, очки, контракты, подсказки и коды — в том числе после
перезапуска сервера и между днями игры.

## Решение

Всё состояние — один объект в памяти процесса, который сбрасывается в
`data/state.json`. Запись с задержкой 200 мс, через временный файл с
переименованием. При выходе по сигналу — синхронная запись. Формат версионируется:
несовместимое сохранение при запуске уезжает в архивный файл рядом, а игра
начинается заново.

## Почему

Тридцать игроков — это несколько десятков килобайт. СУБД добавила бы установку и
настройку на ноутбуке, который увидят впервые за полчаса до игры, и ничего не дала
бы взамен. Атомарная запись нужна потому, что ноутбук на вечеринке закрывают и
уносят без предупреждения. Версионирование — потому что правила менялись несколько
раз, и падение сервера на старых данных хуже, чем честный старт с нуля.

## Последствия

Сервер обязан быть один: два процесса на одном файле состояния затрут друг друга.
Горизонтального масштабирования нет и не будет. Папка `data/` не входит в
репозиторий, поэтому перенос начатой игры — это копирование `state.json` руками.
