# HTTP API

Всё общение — JSON, тексты ошибок сразу на русском и годятся для показа игроку.
Ошибка правил возвращается как `{ "error": "текст", "code": "машинный_код" }` со
статусом 400/401/404/409.

## Авторизация

| Кто | Как |
| --- | --- |
| Игрок | заголовок `x-player-token` (или `?token=` в запросе) |
| Ведущий | заголовок `x-admin-token` (или `?token=`) |

Токен игрока выдаётся при регистрации и живёт в `localStorage` телефона. Токен
ведущего генерируется при первом запуске и печатается в консоли. Если токена игрока
нет или он неизвестен — 401 с кодом `no_session`.

## Маршруты игрока

### GET /api/nickname

Предлагает свободный никнейм тому, кому лень придумывать. Ответ:
`{ nickname }`.

### POST /api/register

Тело: `{ name, nickname }`. Проверяет длину, уникальность обоих полей и что
никнейм не совпадает с именем. Сразу резервирует свободный бейдж, поэтому ответ уже
содержит эмблему, которую игроку предстоит получить. Ответ: `{ token, ...состояние
игрока }`.

Отказ `no_slots` — свободных бейджей нет, ведущему нужно выпустить ещё.

### GET /api/me

Основная ручка: всё состояние игрока одним ответом. Её же клиент опрашивает раз в
8 секунд.

```
game     { status, title }
rules    { hitPoints, missPenalty, defensePoints, ammoMax, ammoRegenMinutes }
me
  id, name, nickname, score, hits, misses
  hasBadge                                     false, пока ведущий не выдал бейдж
  emblem { svg, description, code }             своя эмблема: до выдачи —
                                               зарезервированная, готовым SVG
  ammo, nextAmmoAt, cooldownUntil
  target { nickname }                          только никнейм цели
  hints[], hintsLeft
  attempts[]                                   по кому уже стреляли в этом контракте
  defense { shielded, nextTryAt, identified }
  log[], inbox[]
roster[] { id, name }                          список имён: для выстрела и защиты
board[]  { nickname, score, hits, misses }     табло
```

Связки «никнейм ↔ имя ↔ эмблема» в ответе нет и быть не должно: `target` содержит
только никнейм, `roster` — только имена, `board` — только никнеймы. Это правило
важнее удобства, см. [architecture.md](architecture.md).

### POST /api/shoot

Тело: `{ playerId }` — id из `roster`. Ответ: `{ result, points, cooldownUntil,
ammo, state }`, где `result` — `hit`, `miss` или `blocked`. При попадании
добавляются `victimNickname` и `newTargetNickname`.

Отказы: `no_badge`, `no_target`, `no_ammo`, `cooldown`, `no_player`, `self_shot`,
`already_tried`.

### POST /api/defend

Тело: `{ playerId }` — предполагаемый охотник. Ответ: `{ result, state }`, где
`result`:

- `right` — угадал: плюс `points` и `suspectName`, встаёт щит;
- `wrong` — не угадал: `nextTryAt`, попытка потрачена;
- `no_hunters` — на игрока никто не охотится, попытка **не** тратится.

### POST /api/code

Тело: `{ code }` — код за активность. Ответ: `{ points, hint, hintsExhausted,
hintsLeft, state }`.

Отказы: `no_code`, `code_used` (этот игрок уже вводил), `code_spent` (кончились
использования), `hints_done` (подсказки по цели исчерпаны — код не сгорает).

### POST /api/inbox/read

Помечает входящие прочитанными. Ответ: `{ ok: true }`.

### GET /api/board

Табло без авторизации: `{ board, status }`. Для показа на большом экране.

## Маршруты ведущего

### GET /api/admin/state

Полная картина: настройки, статистика, очередь на выдачу бейджей (`pending`:
имя, никнейм, назначенная эмблема, код, время регистрации), таблица игроков с
эмблемами и целями, коды, лента событий. Тут связки видны — это пульт ведущего.

### POST /api/admin/slots

Тело: `{ count, append }` (count 1–300). Выпускает набор бейджей со
сбалансированными эмблемами. Ответ: `{ count, codes }`.

Без `append` заменяет набор целиком и откажет, если бейджи уже выданы или
зарезервированы. С `append: true` дописывает новые к существующим, продолжая тот же
счётчик эмблем: уже выданные не задеваются, повторов не будет. Всего эмблем 81 —
больше набор атрибутов не даёт.

### POST /api/admin/codes

Тело: `{ count, points, grantsHint, maxUses, note }`. Создаёт коды за активности.
Ответ: `{ created: [коды], ...состояние }`.

### POST /api/admin/game/:action

`action` — одно из: `start` (раздать контракты по кругу и начать), `pause`,
`resume`, `finish`, `reshuffle` (перераздать контракты).

### POST /api/admin/reset

Тело: `{ confirm: "RESET" }`. Полный сброс игры. Без подтверждения — ошибка.

### POST /api/admin/player/:id/score

Тело: `{ delta, reason }`. Ручная правка очков.

### POST /api/admin/player/:id/badge

Ведущий отдал бейдж в руки — игрок входит в игру. Тело: `{ code }` необязательно;
без него выдаётся зарезервированный бейдж, с ним — тот, что фактически отдали
(прежний резерв освобождается). Ответ: `{ code, ...состояние }`.

Отказы: `has_badge` (уже выдан), `no_slot` (кода нет), `slot_taken` (бейдж уже у
кого-то), `slot_reserved` (бейдж зарезервирован за другим — в тексте ошибки указано,
за кем).

### POST /api/admin/player/:id/badge/reassign

Меняет зарезервированную эмблему на другую свободную: бейдж потерялся или испорчен.
Ответ: `{ code, ...состояние }`. Отказы: `has_badge`, `no_slots`.

### POST /api/admin/player/:id/hint

Выдаёт игроку следующую подсказку вручную. Ответ: `{ hint, ...состояние }`.

### POST /api/admin/player/:id/retarget

Меняет игроку цель (на того, у кого меньше всех охотников).

### DELETE /api/admin/player/:id

Удаляет игрока и освобождает его бейдж. Нужно, если человек потерял телефон:
по освободившемуся бейджу можно зарегистрироваться заново, но очки придётся
вернуть вручную.

### PATCH /api/admin/config

Тело — любое подмножество настроек из [game-rules.md](game-rules.md). Неизвестные
ключи игнорируются, числа округляются и не могут быть отрицательными. Ответ:
`{ config }`.

### GET /api/admin/join-qr

`{ url, dataUrl, addresses, port }` — QR для входа игроков и все адреса ноутбука
в локальной сети.

### GET /print

Лист бейджей для печати (HTML, A4, три в ряд): эмблема и код текстом. Сверху —
данные Wi-Fi из настроек. Адрес сервера на лист не попадает, поэтому печатать можно
в любой момент, в том числе до выбора сети.

`?free=1` печатает только невыданные бейджи — для допечатки по ходу игры.
