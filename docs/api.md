# HTTP API

Всё общение — JSON, тексты ошибок сразу на русском и годятся для показа игроку.
Ошибка правил возвращается как `{ "error": "текст", "code": "машинный_код" }` со
статусом 400/401/404/409.

## Авторизация

| Кто | Как |
| --- | --- |
| Игрок | заголовок `x-player-token` (или `?token=` в запросе) |
| Ведущий | заголовок `x-admin-token` (или `?token=`) |

Токен игрока выдаётся при регистрации и живёт в `localStorage` телефона. Токен
ведущего генерируется при первом запуске и печатается в консоли. Если токена игрока
нет или он неизвестен — 401 с кодом `no_session`.

Токен привязан к одному браузеру, поэтому у игрока есть второй способ входа — имя и
PIN из четырёх цифр, придуманный при регистрации, см. `POST /api/login`. PIN хранится
только как хеш (scrypt со своей солью на каждого игрока) и ни в одном ответе не
появляется.

## Маршруты игрока

### GET /api/nickname

Предлагает свободный никнейм тому, кому лень придумывать. Ответ:
`{ nickname }`.

### POST /api/register

Тело: `{ name, nickname, pin }`. Проверяет длину, уникальность имени и никнейма и что
никнейм не совпадает с именем. Сразу резервирует свободный бейдж, поэтому ответ уже
содержит эмблему, которую игроку предстоит получить. Ответ: `{ token, ...состояние
игрока }`.

Отказы: `no_slots` — свободных бейджей нет, ведущему нужно выпустить ещё;
`bad_pin` — PIN не из четырёх цифр; `weak_pin` — четыре одинаковые цифры или цифры
подряд.

### POST /api/login

Тело: `{ name, pin }`. Возвращает тот же токен, что был выдан при регистрации, вместе
с состоянием игрока: прогресс, цель и подсказки сохраняются. Имя сравнивается без
учёта регистра и лишних пробелов.

Отказы: `no_player` — такого имени нет; `no_pin` — у участника PIN не задан;
`bad_pin` (401) — PIN не подходит, в тексте остаток попыток; `locked` (429) — пять
промахов подряд, вход закрыт на 5 минут.

### GET /api/me

Основная ручка: всё состояние игрока одним ответом. Её же клиент опрашивает раз в
8 секунд.

```
game     { status, title, round }               round — номер раунда, 0 до старта
rules    { hitPoints, missPenalty, defensePoints, bountyPoints, ammoMax,
           ammoRegenMinutes }
wanted   null или { nickname, bounty, since, isMe, isMyTarget }
                                               розыск: никнейм публичен, имя нет
me
  id, name, nickname, score, hits, misses
  hasBadge                                     false, пока ведущий не выдал бейдж
  emblem { svg, description, code }             своя эмблема: до выдачи —
                                               зарезервированная, готовым SVG
  ammo, nextAmmoAt, cooldownUntil
  target { nickname }                          только никнейм цели
  hints[], hintsLeft
  attempts[]                                   по кому уже стреляли в этом контракте
  bountyAttempts[]                             то же для текущего розыска, отдельно
  defense { guardId, guardName, guardSetAt, blocked }
                                               своя ставка защиты и сколько
                                               охотников она уже остановила
  log[], inbox[]
roster[] { id, name, note }                    список имён: для выстрела и защиты,
                                               note — своя заметка из блокнота
board[]  { nickname, score, hits, misses }     табло
pulse[]  { at, text }                          обезличенная лента событий
chat[]   { id, at, nickname, text }            салун: подписан никнеймом
```

Связки «никнейм ↔ имя ↔ эмблема» в ответе нет и быть не должно: `target` содержит
только никнейм, `roster` — только имена, `board` — только никнеймы, `chat` и
`pulse` — тоже без имён. Это правило важнее удобства, см.
[architecture.md](architecture.md).

### POST /api/shoot

Тело: `{ playerId, bounty }` — id из `roster`. Ответ: `{ result, points,
cooldownUntil, ammo, state }`, где `result` — `hit`, `miss`, `blocked` или
`bounty`. При попадании добавляются `victimNickname`, `newTargetNickname` и
`bounty` (награда, если цель была в розыске); при `blocked` — `newTargetNickname`
(контракт провален, цель заменена).

Флаг `bounty: true` меняет смысл выстрела: это заявление «этот человек и есть
разыскиваемый», а не «это моя цель». Промах в нём штрафует так же, но
вычёркивается в отдельном списке (`bountyAttempts`) и контракта не касается —
даже если под руку попала собственная цель. Исключение одно: когда разыскиваемый и
есть ваша цель, выстрел считается контрактным и приносит и очки, и награду.

Отказы: `no_badge`, `no_target`, `no_ammo`, `cooldown`, `no_player`, `self_shot`,
`already_tried`, `no_wanted` (розыска сейчас нет), `self_bounty` (в розыске вы сами).

### POST /api/defend

Ставит защиту на предполагаемого охотника. Тело: `{ playerId }` — id из `roster`.
Ответ: `{ result: 'set', suspectName, state }`.

Ответ намеренно одинаков и для верной, и для неверной ставки: правильность игрок
узнаёт только тогда, когда этот человек в него выстрелит. Иначе перебор списка
давал бы информацию бесплатно.

Отказы: `no_badge`, `no_player`, `self_defense`, `same_guard` (ставка уже стоит на
этом участнике).

### POST /api/code

Тело: `{ code }` — код за активность. Ответ: `{ points, hint, hintsExhausted,
hintsLeft, state }`.

Отказы: `no_code`, `code_used` (этот игрок уже вводил), `code_spent` (кончились
использования), `hints_done` (подсказки по цели исчерпаны — код не сгорает).

### POST /api/chat

Сообщение в салун. Тело: `{ text }` (до 200 знаков). Ответ: `{ at, nickname, text,
state }` — подписывается никнеймом игрока, имя в чат не попадает.

Отказы: `not_running`, `no_badge`, `empty_message`, `too_fast` (429, пауза между
сообщениями — несколько секунд).

### POST /api/note

Заметка в блокноте про другого участника. Тело: `{ playerId, text }` (до 40
знаков; пустая строка стирает заметку). Ответ: `{ playerId, note, state }`.

Заметки личные: они приходят только их автору, внутри `roster`.

Отказы: `no_player`, `self_note`.

### POST /api/inbox/read

Помечает входящие прочитанными. Ответ: `{ ok: true }`.

### GET /api/board

Табло без авторизации: `{ board, status }`. Для показа на большом экране.

## Маршруты ведущего

### GET /api/admin/state

Полная картина: настройки, статистика, очередь на выдачу бейджей (`pending`:
имя, никнейм, назначенная эмблема, код, время регистрации), таблица игроков с
эмблемами и целями, коды, лента событий. Тут связки видны — это пульт ведущего.

Розыск приходит двумя полями: `wanted` — `{ name, nickname, bounty, since }` с
настоящим именем, чтобы ведущий знал, о ком речь, и `wantedPauseUntil` — до какого
момента розыск молчит после выплаты награды (0, если не молчит). Салун — в `chat`,
где к каждому сообщению добавлено `name` автора.

### POST /api/admin/slots

Тело: `{ count, append }` (count 1–300). Выпускает набор бейджей со
сбалансированными эмблемами. Ответ: `{ count, codes }`.

Без `append` заменяет набор целиком и откажет, если бейджи уже выданы или
зарезервированы. С `append: true` дописывает новые к существующим, продолжая тот же
счётчик эмблем: уже выданные не задеваются, повторов не будет. Всего эмблем 81 —
больше набор атрибутов не даёт.

### POST /api/admin/codes

Тело: `{ count, points, grantsHint, maxUses, note }`. Создаёт коды за активности.
Ответ: `{ created: [коды], ...состояние }`.

### DELETE /api/admin/chat/:id

Удаляет сообщение из салуна. Ответ — состояние пульта. Отказ: `no_message`.

### POST /api/admin/game/:action

`action` — одно из: `start` (раздать контракты по кругу и начать), `pause`,
`resume`, `finish`, `reshuffle` (перераздать контракты).

`start` начинает раунд и увеличивает `game.round`. Со второго раунда он ещё и
перетасовывает никнеймы между участниками, стирает салун, журналы выстрелов,
уведомления, защиты и розыск; очки, попадания, заметки и бейджи остаются. Пока
раунд идёт, повторный `start` отказывает (`already_running`): сначала `finish`.

### POST /api/admin/reset

Тело: `{ confirm: "RESET" }`. Полный сброс игры. Без подтверждения — ошибка.
Перед сбросом состояние копируется в `data/state.json.before-reset-<время>`:
коды на уже напечатанных бейджах после сброса становятся чужими, и вернуть игру
можно только из копии.

### POST /api/admin/player/:id/score

Тело: `{ delta, reason }`. Ручная правка очков.

### POST /api/admin/player/:id/badge

Ведущий отдал бейдж в руки — игрок входит в игру. Тело: `{ code }` необязательно;
без него выдаётся зарезервированный бейдж, с ним — тот, что фактически отдали
(прежний резерв освобождается). Ответ: `{ code, ...состояние }`.

Отказы: `has_badge` (уже выдан), `no_slot` (кода нет), `slot_taken` (бейдж уже у
кого-то), `slot_reserved` (бейдж зарезервирован за другим — в тексте ошибки указано,
за кем).

### POST /api/admin/player/:id/badge/reassign

Меняет зарезервированную эмблему на другую свободную: бейдж потерялся или испорчен.
Ответ: `{ code, ...состояние }`. Отказы: `has_badge`, `no_slots`.

### POST /api/admin/player/:id/pin/reset

Забытый PIN: выдаёт новый случайный из четырёх цифр и снимает блокировку входа.
Ответ: `{ pin, ...состояние }` — единственное место, где PIN появляется в открытом
виде, и только ведущему, чтобы он назвал его игроку. Прежний PIN перестаёт работать.

### POST /api/admin/player/:id/hint

Выдаёт игроку следующую подсказку вручную. Ответ: `{ hint, ...состояние }`.

### POST /api/admin/player/:id/retarget

Меняет игроку цель (на того, у кого меньше всех охотников).

### DELETE /api/admin/player/:id

Удаляет игрока и освобождает его бейдж вместе с резервом. Для потерянного доступа
это не нужно — есть вход по PIN и сброс PIN; удаление стирает очки и историю.

### PATCH /api/admin/config

Тело — любое подмножество настроек из [game-rules.md](game-rules.md). Неизвестные
ключи игнорируются, числа округляются и не могут быть отрицательными. Ответ:
`{ config }`.

### GET /api/admin/join-qr

`{ url, dataUrl, addresses, interfaces, port }` — QR для входа игроков и все адреса
ноутбука в локальной сети. `interfaces` — те же адреса, но с именем адаптера и
подсетью (`{ name, address, subnet }`): по самому адресу не понять, в какую сеть он
ведёт.

### GET /print

Лист бейджей для печати (HTML, A4, три в ряд): эмблема и код текстом. Сверху —
данные Wi-Fi из настроек. Адрес сервера на лист не попадает, поэтому печатать можно
в любой момент, в том числе до выбора сети.

`?free=1` печатает только невыданные бейджи — для допечатки по ходу игры.
